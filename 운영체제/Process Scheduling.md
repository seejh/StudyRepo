# 프로세스 스케줄링
OS가 프로세스를 관리하고 스케줄링하는 내용<br/>

## 프로세스
프로세스는 실행 중인 프로그램이다. 우리가 c++로 소스 코드를 작성하고 컴파일할 때 컴파일러는 실행 가능한 바이너리 파일을 생성한다. 이 실행 파일을
프로그램이라고 부른다. 프로그램이 메모리에 로드되어 실행되면 프로세스가 된다.

### 프로세스의 메모리 배치
메모리 내에서 프로세스는 여러 개의 섹션으로 나뉘며 각각 서로 다른 목적을 수행한다.<br/>
<img width="182" height="339" alt="image" src="https://github.com/user-attachments/assets/27558821-7aa0-4d70-91da-7e7c5a41acbb" /><br/>

* Text (텍스트 영역)
  * 텍스트, 코드 영역에는 실행 가능한 명령어가 포함되어 있다.
  * 보통 읽기 전용이다.
* Stack (스택 영역)
  * 함수의 매개변수, 반환 주소, 로컬 변수와 같은 임시 데이터가 있다.
* Data (데이터 영역)
  * 전역 변수를 포함한다.
* Heap (힙 영역)
  * 프로세스 실행 중에 동적으로 메모리를 할당한다.

## 프로세스 속성, PCB
프로세스에는 운영체제가 프로세스를 관리하고 제어하는 데 필요한 여러 속성을 저장한다. 이 속성들은 프로세스 제어 블록(PCB)에 저장되며 PCB는 OS가 관리하고
OS에 저장된다.<br/>
<img width="314" height="392" alt="image" src="https://github.com/user-attachments/assets/092a4013-c090-4114-b7a2-d63e452e0348" /><br/>

* 프로세스 상태 (Process State)
  * 실행, 대기, 준비, 종료 등 프로세스의 상태를 나타낸다.
* 프로세스 번호 (PID)
  * 모든 프로세스는 PID라는 고유 ID가 할당된다.
* 프로그램 카운터 (Program Counter)
  * PC는 CPU 레지스터 중 하나로 다음에 수행할 명령어의 주소를 저장하는 곳이다.
  * PCB에서 이 PC 값을 저장해두고 다음에 프로세스를 복원할 때 PC로 복원한다.
* 레지스터 (CPU Registers)
  * 그 밖의 CPU 레지스터 값들
* 메모리 정보
* 오픈 파일 목록

## 프로세스 관리 (Process Management)
프로세스 관리는 운영체제의 핵심 기능이다. 효율적인 CPU 활용과 원활한 시스템 성능을 보장하기 위해 

### 프로세스 관리 작업
* 프로세스 생성 및 종료
* CPU 스케줄링
* 교착 상태 처리 (Deadlock Handling)
* 프로세스 간 통신 (IPC, Interprocess Communication)
* 프로세스 동기화 (Synchronization)

## 프로세스 상태 (Process State)
프로세스가 실행되고 종료될 때까지의 수명 주기(Life Cycle)에 따른 상태 변화<br/>
<img width="588" height="284" alt="image" src="https://github.com/user-attachments/assets/d6fc6a6f-84fe-4f63-8201-e70bc2eb87c9" /><br/>
* New
  * 프로그램은 디스크에 존재하고 OS가 PCB를 준비한 후 메인 메모리에 올리면 Ready 상태로 간다.
* Ready
  * 프로세스가 메인 메모리에 로드되어 실행 준비가 된 상태.
  * CPU를 할당 받을 때까지 준비 큐에서 대기한다.
* Running
  * CPU가 현재 프로세스의 명령어를 실행 중.
* Blocked/Waiting
  * I/O의 완료, 사용자 입력, 잠긴 자원에 대한 접근과 같은 이벤트를 기다리고 있어 프로세스가 계속될 수 없는 상태.
  * 이벤트가 완료되면 Ready 상태로 돌아간다. 
* Terminated
  * 프로세스가 실행을 완료했거나 중단된 상태.
  * OS가 PCB를 삭제하고 할당된 모든 자원을 해제한다.
* Suspend Ready, Suspend Blocked/Waiting
  * Suspend = 메모리 부족으로 인해서 디스크로 스왑 아웃.
  * 메모리가 확보되면 본래 상태로 돌아간다.

### 스케줄러
<img width="508" height="266" alt="image" src="https://github.com/user-attachments/assets/048746f5-c419-497e-ac19-92010509ad2c" /><br/>
* 장기(Long-Term) 스케줄러
  * 아직 실행되지 않은 디스크에 저장된 프로그램(Job)을 선별하여 메모리에 로드하는 역할
  * 잡(Job) 스케줄러라고도 하며 실행 주기가 가장 느리다.
  * New -> Ready
* 단기(Short-Term) 스케줄러
  * CPU 스케줄러라고도 하며 실행 주기가 가장 빠르다.
  * Ready 큐에서 CPU를 할당 받을 프로세스를 선택한다.
  * Running -> Ready
* 중기(Medium-Term) 스케줄러
  * 메모리 공간이 부족하면 중기 스케줄러가 개입하여 스와핑(Swapping) 한다.
  * Swap-out: 메모리 공간을 확보하기 위해 현재 실행 중이지 않거나 우선순위가 낮은 프로세스를 디스크로 이동시킨다. 이때 프로세스는 Suspended 상태가 된다.
  * Swap-in: 여유 메모리가 생기거나 스왑 아웃된 프로세스가 다시 CPU를 할당 받아야 할 때 디스크에서 다시 메모리로
  * Swapper 라고도 하며 필요할 때 수시로 작동한다.
  * suspended state <-> state

* Running->Waiting
  * 프로세스가 스스로 CPU를 양보한 것으로 스케줄러 개입 X<br/>
* Running->Ready
  * 프로세스가 cpu를 할당 받을 때 OS는 해당 프로세스에게 사용할 기간 time slice 동안만 허용한다.
  * 지정된 시간이 만료되면 타이머 인터럽트가 발생한다.
  * 프로세스가 OS에 의해 선점 당하는 것이며 단기 스케줄러에 의해 발생한다.

### 선점 (Preemption)
선점(Preemtion): 프로세스가 CPU에서 강제로 제거된다.
비선점, 선점 방지(Non-Preemtion): 프로세스는 실행이 완료될 때까지 제거될 수 없다.

## 컨텍스트 스위칭
한 프로세스에서 다른 프로세스로 전환할 때 현재 프로세스의 컨텍스트를 저장하고 다음 프로세스를 불러온다.
이 전환을 컨텍스트 스위칭이라고 한다. 컨텍스트 스위칭은 동시에 여러 일을 하는 것처럼 보이게 만드는 멀티태스킹에서
필수적인 대가이다.<br/>

### 컨텍스트 스위칭 트리거
* 현재 실행중인 프로세스보다 더 높은 우선순위를 가진 프로세스가 READY일 때
* 인터럽트가 발생할 때
* 유저 모드와 커널 모드 전환이 발생할 때(필수는 아님)
* 선점형(Preemptive) CPU 스케줄링이 사용될 때

### 컨텍스트 스위칭 과정
프로세스 p0와 p1이 교차로 실행하고 그에 따라 현재 프로세스 컨텍스트를 저장, 불러오는 것을 보여주는 그림<br/>
<img width="625" height="317" alt="image" src="https://github.com/user-attachments/assets/0b2f24ef-f047-4bf6-b97b-209263147b4b" /><br/>
* 1.p0 실행 중
  * p0 현재 실행 중, p1 유휴 상태, 그러던 중 시스템 콜 어느 시점에 발생.
* 2.p0 현재 상태 저장
  * OS는 p0를 일시 정지 후 p0의 현재 상태(레지스텁 값, 프로그램 카운터 등)를 PCB(0)에 저장.
* 3.p1 상태 로딩
  * OS PCB(1)에서 저장된 상태를 가져와서 복원 후 마지막 저장 지점에서 실행을 계속한다.
* 4.p1 실행 중
  * 이제 p1이 실행 중이고 p0는 유휴 상태이다.
* 5.p1 상태 저장
* 6.p0 상태 로딩
* 7.p0 실행 중

### 오버헤드
컨텍스트 스위칭에 소요되는 시간을 컨텍스트 스위치 오버헤드라고 한다. 이 시간 동안 cpu는 프로세스 작업을 

* 이러한 전환에 소요되는 시간을 컨텍스트 스위치 오버헤드라고 한다.
* 이 시간 동안 CPU는 프로세스 작업을 수행하지 않고 준비가 되기를 기다린다.
* 컨텍스트 스위칭이 너무 자주 일어나면 CPU 효율이 떨어진다.

### 컨텍스트 스위칭 오버헤드에 영향을 미치는 요인
컨텍스트 스위칭 시간은 하드웨어 지원에 크게 의존한다.

* 빠른 레지스터 저장/로딩을 위한 하드웨어 지원
* 레지스터 수 (레지스터 수 증가 => 저장/로드 시간 증가)
* PCB 저장 공간의 메모리 속도
* OS 커널 코드의 효율성
