# 프로세스 스케줄링

## OS에서 프로세스
프로세스는 실행 중인 프로그램이다. 우리가 c++로 소스 코드를 작성하고 컴파일할 때 컴파일러는 실행 가능한 바이너리 파일을 생성한다. 이 실행 파일을
프로그램이라고 부른다. 프로그램이 메모리에 로드되어 실행되면 프로세스가 된다.

### 프로세스의 메모리 배치
메모리 내 프로세스는 여러 개의 뚜렷한 섹션으로 나뉘며 각각 서로 다른 목적을 수행한다.<br/>
<img width="182" height="339" alt="image" src="https://github.com/user-attachments/assets/27558821-7aa0-4d70-91da-7e7c5a41acbb" /><br/>
* Text (텍스트 영역)
  * 텍스트 또는 코드 영역에는 실행 가능한 명령어가 포함되어 있다. 보통 읽기 전용이다.
* Stack (스택 영역)
  * 함수의 매개변수, 반환 주소, 로컬 변수와 같은 임시 데이터가 포함된다.
* Data (데이터 영역)
  * 전역 변수를 포함한다.
* Heap (힙 영역)
  * 프로세스 실행 중에 동적으로 메모리를 할당한다.

### 프로세스 속성, PCB
프로세스는 운영체제가 관리하고 제어하는 데 도움이 되는 여러 중요한 속성을 가지고 있다. 이 속성들은 프로세스 제어 블록(PCB)에 저장된다.

PCB는 OS에 저장


# 프로세스 관리, Process Management Introduction
프로세스 관리는 운영체제의 핵심 기능이다. 멀티태스킹 환경에서 효율적인 CPU 활용과 원활한 시스템 성능을 보장하기 위해 프로세스를 생성, 스케줄링, 조정하는 것을 다룬다.

* 프로세스 생성 및 종료
  * 프로세스를 생성하는 과정에는 프로세스 ID 생성, PCB 설정 등의 과정이 포함된다.
  * 프로세스를 종료하는 과정에는 프로세스에 할당된 모든 자원을 정리하는 과정이 포함된다.
* CPU 스케줄링
  * 멀티프로그래밍, 멀티태스킹 시스템에서는 여러 프로세스가 CPU를 받아야 한다.
  * 운영체제는 여러 프로세스가 원활하고 효율적으로 실행되도록 보장해야 한다.
* 교착 상태 처리
  * 시스템이 교착 상태에 걸리지 않게 보장한다.
* 프로세스 간 통신
  * 프로세스간 통신 가능하도록 공유 메모리와 메시지 전달 등의 기능을 제공한다.
* 프로세스 동기화
  * 여러 프로세스의 실행을 조정하여 이들이 공유 자원(예: 메모리)에 접근할 때 통제되고 예측 가능하게 접근하도록 하는 것이다.



### CPU 바운드 프로세스, I/O 바운드 프로세스
* CPU 바운드 프로세스
  * CPU 바운드 프로세스는 더 많은 CPU 시간을 필요로 하고 실행 상태에서 더 많은 시간을 보낸다.
* I/O 바운드 프로세스
  * cpu는 I/O 장치보다 훨씬 빠르기 때문에 프로세스가 I/O를 할 때 CPU는 대기상태가 아니어야 한다.(Blocked)
  * 현재 실행중인 프로세스가 I/O를 수행 중일 때 다른 프로세스에게 CPU를 할당하여 CPU 활용도를 높인다.

# 컨텍스트 스위칭
컨텍스트 스위칭은 CPU가 한 프로세스의 실행을 멈추고 현재 상태를 저장한 후 다른 프로세스의 저장된 상태를 로드하여,
여러 프로세스가 CPU를 효과적으로 공유할 수 있도록 하는 과정이다.<br/>

### 멀티태스킹의 필요성
많은 프로세스가 CPU 시간을 필요로 하는 ___멀티태스킹___ 시스템에서 필수적이다. 멀티태스킹에서는 CPU가 계속해서 프로세스를 전환한다.
이로 인해 CPU는 한 번에 한 프로세스만 처리하는데도 ___여러 프로세스를 동시에 실행하는 것처럼 보인다.___ 컨텍스트 스위칭이 없다면 독점이
일어날 수 있고 다른 프로세스들이 많이 기다려야 한다.

### 스케줄링에서의 역할
스케줄러는 스케줄링 알고리즘을 기반으로 다음 실행할 프로세스를 결정한다. 컨텍스트 스위칭은 현재 프로세스를 멈추고 선택한 프로세스를 시작함으로써
그 결정을 실행한다. 디스패처는 스케줄링된 목록을 실제로 수행한다.

### 컨텍스트 스위칭 트리거
* 현재 실행중인 프로세스보다 더 높은 우선순위를 가진 프로세스가 READY일 때
* 인터럽트가 발생할 때
* 유저 모드와 커널 모드 전환이 발생할 때(필수는 아님)
* 선점형(Preemptive) CPU 스케줄링이 사용될 때

### 컨텍스트 스위칭 과정
프로세스 p0, p1이 교차하며 실행되는 상황이고 교차할 때 발생하는 컨텍스트 스위칭에 대해서 표현한 그림<br/>
<img width="625" height="317" alt="image" src="https://github.com/user-attachments/assets/0b2f24ef-f047-4bf6-b97b-209263147b4b" /><br/>
1. p0 실행 중
* p0 실행 중이고 p1은 유휴 상태.
* 어떤 시점에 인터럽트나 시스템 콜 발생.
2. p0 현재 상태 저장
* 운영체제는 p0를 일시정지 후 p0의 현재 상태(레지스터 값, 프로그램 카운터 등)를 PCB(0)에 저장한다.
* 이로 인해 p0는 나중에 중단된 지점에서 다시 시작할 수 있다.
3. p1 상태 로딩
* 운영체제는 PCB(1)에서 저장된 상태를 가져와서 복원 후 마지막 저장 지점에서 실행을 계속한다.
4. p1 실행 중
* 이제 p1이 실행 중이고 p0는 유휴 상태이다.
* 이후 또 다른 인터럽트나 시스템 콜이 발생하여 컨텍스트 스위칭이 또 트리거된다.
5. p1 상태 저장
6. p0 상태 로딩
7. p0 실행 중

### 오버헤드
* 이러한 전환에 소요되는 시간을 컨텍스트 스위치 오버헤드라고 한다.
* 이 시간 동안 CPU는 프로세스 작업을 수행하지 않고 준비가 되기를 기다린다.
* 컨텍스트 스위칭이 너무 자주 일어나면 CPU 효율이 떨어진다.

### 컨텍스트 스위칭 오버헤드에 영향을 미치는 요인
컨텍스트 스위칭 시간은 하드웨어 지원에 크게 의존한다.

* 빠른 레지스터 저장/로딩을 위한 하드웨어 지원
* 레지스터 수 (레지스터 수 증가 => 저장/로드 시간 증가)
* PCB 저장 공간의 메모리 속도
* OS 커널 코드의 효율성

# 스케줄러, 디스패처
멀티태스킹 운영체제에서 여러 프로세스가 CPU 시간을 두고 경쟁한다. 이를 효율적으로 관리하기 위해 운영체제는 두 가지 중요한 구성 요소인
스케줄러와 디스패처를 사용한다.

### 디스패처
<img width="618" height="190" alt="image" src="https://github.com/user-attachments/assets/8ffdde85-1774-4300-8c01-49cf6da2d52c" /><br/>
단기 스케줄러가 선택한 프로세스에 CPU 제어권을 주는 특수한 프로그램이다.

### 스케줄러
<img width="622" height="312" alt="image" src="https://github.com/user-attachments/assets/f1bbf024-9baa-419f-a0af-eb519ee1586b" /><br/>
어떤 프로세스가 CPU 시간을 할당 받을지를 결정한다. CPU를 효율적으로 사용하고 여러 프로세스들을 원활하게 실행하는 것을 보장한다.
스케줄러에는 세 가지 유형이 있으며 각각 프로세스 관리에서 서로 다른 작업을 수행한다.<br/>

* 장기 스케줄러
  * 프로세스를 보조 메모리(작업 풀)에서 주 메모리(준비 큐)로 이동시킨다.
* 중기 스케줄러
  * 시스템 상태에 따라 프로세스를 일시 중지하거나 재개한다.
* 단기 스케줄러
  * 메모리에서 준비된 프로세스 중 하나를 지정하여 실행되게 만든다.
