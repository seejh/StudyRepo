## 논리 메모리, 물리 메모리

* Logical address (=Virtual address)
  * 프로세스마다 독립적으로 가지는 주소 공간으로 각 프로세스마다 0번지부터 시작
  * cpu가 보는 주소는 logical address
* Physical address
  * 실제 메모리 주소

### 주소 바인딩
```
symbolic address -> logical address -> physical address

// symbolic address: 프로그래밍할 때 사람이 이해하기 쉬운 기호로 메모리 주소를 가리키는 거
```
cpu와 프로세스가 사용하는 주소는 가상의 논리 주소이고 이는 실제 메모리 주소에 매핑되어야 한다.
가상 주소가 실제 메모리에 바인딩(매핑)되는 시점이 언제인가<br/>
<img width="841" height="584" alt="image" src="https://github.com/user-attachments/assets/dac64bba-c076-4940-8eb8-4e19e04ef0d5" /><br/>
* 컴파일(Compile) 타임 바인딩
  * 컴파일할 때 물리 주소가 결정되며 요새는 사용하지 않는다. 
* 로드(Load) 타임 바인딩
  * 프로그램을 로드할 때(실행) 물리 주소가 결정된다.
* 런(Run, Execute) 타임 바인딩
  * 로드 타임과 같으나 실행 중에 물리 주소가 변동될 수 있다.

* 그림 해석
  * 컴파일 타임
    * 컴파일하여 논리 주소가 0~~40으로 결정.
    * 이 주소가 실행하면 곧 물리 주소이다.
  * 로드 타임
    * 컴파일하여 논리 주소가 0~40으로 결정.
    * 프로그램을 실행하면 500~530으로 물리 주소가 결정되고 해당 위치로 고정된다.
  * 런 타임
    * 컴파일하여 논리 주소가 0~40으로 결정.
    * 실행하면 300~~330으로 물리 주소가 결정되었으나 실행 중에 700~730으로 변경되었다.

cpu나 프로세스는 주소를 논리 주소로 다루고 런 타임의 경우 실 물리 주소가 변동될 수 있기에 접근할 때 마다 확인이 필요하다.
이러한 것은 하드웨어적으로 처리한다.(MMU)<br/>

### MMU (Memory Management Unit)
<img width="789" height="558" alt="image" src="https://github.com/user-attachments/assets/2b27c120-b0d9-4363-8bac-4a558af09066" /><br/>
프로세스와 cpu에서 접근하는 모든 주소는 논리 주소이며 실제 물리 주소를 알지 못한다. 이를 변환해주는 것이 MMU로, MMU는 논리 주소를 물리 주소로 변환해주는
하드웨어 디바이스(소프트웨어가 아닌)이다.<br/>

* 위 그림에서 프로세스 p1은 논리 주소 0~3000, 실제 물리 주소로는 14000~17000을 할당 받은 상태이다.
* cpu에서 논리 주소 346에 액세스하면 mmu에서 "346 + base register(=relocation register) = 14346" 하여 찾아간다.
* base register는 프로세스가 할당 받은 물리 주소의 시작점을 나타낸다.
* 논리 주소는 0부터 시작하는 가상 주소로 이는 결국 오프셋(얼마만큼 떨어져 있는지)이라는 것이다.
* 그래서 "액세스할 실제 물리 주소 = base register(시작 물리 주소) + 논리 주소(오프셋)"이 된다.

<img width="672" height="334" alt="image" src="https://github.com/user-attachments/assets/70f2cf56-e3cd-4f3a-9596-5b3cdbbba493" /><br/>
limit register라는 것도 있는데, 이는 해당 프로세스가 할당 받은 메모리 영역을 넘는(다른 곳을 침범하는) 행위를 막기 위한 것으로 넘으면 os가 trap을 건다.
limit register의 값은 논리 주소 범위, 해당 프로세스가 할당 받은 메모리양이다.<br/>
