# 가상 메모리 (Virtual Memroy)
실제 물리 메모리 접근에 운영체제는 관여하지 않는다. 가상 메모리 접근에는 관여를 한다.<br/>
여기서부터는 앞에서 배운 메모리 할당 방식에서 paging 기법을 사용하는 것을 전제로 한다. (대다수 시스템에서 paging을 사용한다)

## Demand Paging
논리 메모리인 페이지를 실제로 필요할 때 물리 메모리에 올리는 것.

* I/O 감소
* Memory 사용량 감소
* 빠른 응답 시간
  * 한정된 공간에서 필요하지 않을 때 미리 다 올려 놓는 것에 비해 필요한 것만 올려서 메모리 히트율을 올려서 빠르다는 것
* 더 많은 사용자 수용

* 페이지가 물리적 메모리에 없음

### Page Fault
논리 메모리의 페이지가 현재 물리 메모리의 프레임에 할당되어 있지 않은 경우, 페이지 테이블 엔트리에 invalid bit가 set되어 있는 경우.
<img width="396" height="505" alt="image" src="https://github.com/user-attachments/assets/4a9d2fd4-b468-4f2e-8cdb-fe9a8348bd34" /><br/>
위 그림에서 페이지 0, 2, 5는 (v)alid로 물리적 메모리(프레임)가 할당되어 있는 상태이다.<br/>

* 페이지 폴트 동작 과정
  * 주소 변환 -> mmu에서 페이지 테이블 조회, invalid -> mmu에서 page fault trap 발생
  * 커널에서 cpu 선점, 커널 모드로 진입, page fault handler 호출
  * page fault handler
    * 접근 유효성 검사 (잘못된 접근이면 segmentation fault)
    * 빈 프레임 할당 (없으면 다른 프레임의 자리를 뻇는다: page replacement)
    * 디스크에서 해당 페이지를 프레임에 로드한다. (디스크 I/O)
    * 페이지 테이블 갱신 후 해당 프로세스를 ready로 변경
    * 프로세스가 이후에 cpu를 할당 받게 되면 중단된 곳부터 수행

물리 주소에 대한 접근은 운영체제(커널)에서는 하지 않으며 mmu (하드웨어)에서 페이지 테이블 후 page fault trap을 걸면 운영체제가
개입하여 절차를 수행하게 된다. 페이지 폴트는 디스크 I/O가 필요한 오래 걸리는 작업이기에 cpu를 커널에게 선점 당하는(block) 오버헤드가
큰 작업이다.

### Thrashing
프레임(메모리) 부족으로 프로세스 수행 시간보다 페이지 교체에 소요되는 시간이 더 많아져 시스템 성능이 떨어지는 것<br/>
<img width="676" height="391" alt="image" src="https://github.com/user-attachments/assets/439a4f4f-c5be-4d03-8efc-ba2df9ad1194" /><br/>
다중 프로그래밍 정도에 따라 cpu 활용률이 늘어나다가 어느 기점에서 cpu 활용률이 급격하게 떨어지는 모습<br/>

* 원인: 프레임(메모리 부족)
  * 다중 프로그래밍 정도 과다
* 해결
  * 메모리 증설
  * 다중 프로그래밍 정도 조절
  * working set, PFF 알고리즘 사용

### page size 변경
page size를 감소시키면...

* 페이지 수 증가
* 페이지 테이블 증가
* 메모리 이용 효율 올라감
