# 헤더, 소스 분리 이유

### 컴파일 속도 향상
c++에서는 소스 파일 단위로 컴파일되고 다른 곳에 정의되어 있는 것을 사용하기 위해서
알아야할 것은 타입 정보이다. 정의는 타 cpp 파일에서는 알 필요가 없다.<br/>

따라서 컴파일에 필요한 타입 정보만 헤더 파일에 두고 구현 내용은 cpp 파일로 분리하면
이 헤더 파일을 포함한 다른 소스 파일을 컴파일할 때 구현 내용을 함께 처리하지 않아도 된다.
이 결과 컴파일에 낭비하는 시간을 줄이게 된다.

### 순환 참조 문제(Circular Dependency)
A.h 파일이 B.h를 include<br/>
B.h 파일이 A.h를 include<br/>

컴파일러는 전처리 단계에서 #include 문을 만나면 해당 헤더 파일의 코드를 그 자리에 그대로
복사해서 붙여 넣는다. 위 상황에서 컴파일러가 두 파일을 번갈아가며 복사 붙여 넣기 루프가 발생하게 된다.<br/>

#### 헤더 가드, #pragma once가 있는데요?
정의되지 않은 타입(Unknown Type) 에러 발생하게 된다.
```
// A.h
#include"B.h"

class A { ... };

// B.h
#include"A.h"

class B {
void B() {
  A a;
}
};

컴파일러가 a.h 읽음
a.h 상단에서 #include"B.h", b.h를 복사
b.h 읽는 도중 #include"A.h", 헤더 가드에 의해 무시
#include"a"를 지나쳐서 B.h를 계속 읽는 중에 A 클래스를 사용하는 부분이 나옴
컴파일러 입장에서 아직 A 클래스를 정의해 본 적이 없으므로 알 수 없는 식별자라며 컴파일 에러
```
