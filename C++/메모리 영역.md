# 메모리 영역
### PE(Portable Executable) 파일
윈도우의 실행 파일(exe, dll, obj, sys, ...)<br/>

### DOS Header, Stub
가장 위에 위치한 영역으로 DOS 환경에서 실행할 코드를 포함.<br/>
윈도우에서 사용하지 않으며 MS-DOS 같은 DOS 환경에서 실행하면 사용되는 영역.<br/>
보통 "This program cannot be run in DOS mode."라는 메시지만 출력하고 끝낸다.<br/>

### NT Header
Signature, FileHeader, Optional Header로 구성<br/>
```c++
// NT 헤더 구조체
typedef struct _IMAGE_NT_HEADERS {
  DWORD Signature;
  IMAGE_FILE_HEADER FileHeader;
  IMAGE_OPTIONAL_HEADER OptionalHeader;
} IMAGE_NT_HEADERS, *PIMAGE_NT_HEADERS;

// FileHeader, OptionalHeader
typedef struct _IMAGE_FILE_HEADER { ... }
typedef struct _IMAGE_OPTIONAL_HEADER { ... }
```
Signature는 PE로 고정<br/>
FileHeader: 타겟 아키텍처 유형, 섹션 수, 타임스탬프, COFF 기호 테이블, 
기호 테이블의 기호 수, Optional Header의 크기 등<br/>
Optional Header: 이미지가 로드될 주소(ImageBase), 이미지 버전, Entry Point, 서브시스템 유형 등이 포함<br/>

ImageBase는 PE 이미지가 로드될 가상 메모리 주소로 기본적으로 EXE 파일은 0x00400000, 
DLL 파일은 0x10000000, 드라이버(SYS) 파일은 0x00010000로 설정되어 있다. 
물론 이 값은 개발자가 직접 바꿀수도 있다. 참고로 시스템 DLL(ntdll.dll, kernel32.dll, user32.dll 등)들은 
특정 메모리 주소에만 로드되도록 ImageBase 값이 설정되어 있다.<br/>

만약에 로드될 메모리 주소에 이미 다른 PE 이미지가 로드되어 있다면 재배치 작업을 통해 다른 메모리 주소에 로드된다.
따라서 PE 이미지가 어느 메모리 주소에 로드될 지 알 수 없기 때문에 헤더 상의 Entry Point 등은 
절대적 주소가 아닌 상대적 주소(RVA)로 되어 있다. 
예로 들면 main 함수의 주소를 구해서 호출하려고 한다면 
(현재 PE 이미지가 로드되어 있는 메모리 주소) + (헤더 상의 상대적 Entry Point 주소)로 하여 호출하게 된다.

### Section Header
NT Header 다음으로 위치한 영역, 섹션에 대한 정보를 가지고 섹션 수 만큼 존재한다.<br/>
* text 영역
  * 프로그램 코드가 있는 영역
* data 영역
  * 전역/static 변수가 있는 영역
* rdata 영역
  * 읽기 전용(const) 변수가 있는 영역
* rsrc 영역
  * 리소스 데이터(사진, 음악 등)가 있는 영역
* PAGE 영역
  * 커널 및 드라이버 전용
  * 
* INIT 영역

동적 라이브러리 메모리 공유

OS의 가상 메모리 시스템, 페이지 매핑 기술 사용하여
물리 메모리에 단 한번만 여러 프로세스가 나눠쓰는 방식


어떤 프로그램이 동적 라이브러리를 처음 요청하면 운영체제는 해당 라이브러리의 코드(텍스트) 영역을 실제
물리 메모리에 딱 한 번만 올린다.

이후 다른 프로세스가 동일한 라이브러리를 실행할 때, 물리 메모리에 새로 로드하는 것이 아니라
해당 다른 프로세스의 가상 메모리 공간에 실제 물리 메모리에 올라와 있는 동적 라이브러리 주소(텍스트)를 매핑 시킨다.

라이브러리 내부의 모든 요소가 공유되는 것은 아니다.
코드(text) 영역은 100 공유하되 전역 변수나 정적 변수들이 저장되는 데이터 영역(BSS)
