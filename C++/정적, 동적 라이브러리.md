# 정적 라이브러리
컴파일 타임에 링킹되며 라이브러리 코드가 실행 파일에 포함되는 형태로 라이브러리 코드가 실행 파일에
포함되어 있기에 실행 파일만 배포하면 된다. <br/>

하지만 그렇기에 실행 파일의 크기가 커지게 되며 해당 라이브러리를 사용하는
프로그램이 시스템에 1개가 아닐 경우에 메모리 효율은 떨어지게 된다.

### 정적 라이브러리 생성
```c++
1. 프로젝트 생성
비주얼 스튜디오 -> 새 프로젝트 생성 -> 정적 라이브러리(MyMathLib)
// MyCalculator.h
class MyCalculator {
public:
  void Add(int value);
  void Sub(int value);
  void GetTotal() const;
private:
  int m_total;
};

// MyCalculator.cpp
void MyCalculator::Add(int value) { m_total += value; }
void MyCalculator::Sub(int value) { m_total -= value; }
void MyCalculator::GetTotal() const { return m_total; }

// pch.h
#ifndef PCH_H
#define PCH_H
#include<iostream>
#endif
```
위 내용 작성 후 빌드를 하면 .lib 파일이 생긴다.<br/>

### 정적 라이브러리 링크
본 프로젝트에서 정적 라이브러리를 링크하려면 아래 3단계를 거쳐야 한다.
```
1. 헤더 파일 경로
프로젝트 속성 -> c/c++ -> 일반 -> 추가 포함 디렉토리 -> 헤더 파일 경로

2. 라이브러리 경로
프로젝트 속성 -> 링커 -> 일반 -> 추가 라이브러리 디렉토리 -> .lib 파일이 있는 폴더

3. 사용할 라이브러리 명시
프로젝트 속성 -> 링커 -> 입력 -> 추가 종속성 -> .lib 파일
또는 #pragma comment(lib, ".lib 파일") 으로도 가능하다.
```



#### 정적 라이브러리 PCH
라이브러리 내부 소스들만 PCH의 이점을 누리고, 외부 프로젝트에는 아무런 영향을 주지 않는 것이 정상
메인 프로젝트에 pch.h를 강제하면 안된다.
배포용 헤더에는 pch 코드를 넣으면 안 된다.

# 동적 라이브러리
런타임(프로그램 실행 중)에 라이브러리를 불러오는 방식<br/>
묵시적 링킹, 명시적 링킹 2가지가 있다.<br/>

동적 라이브러리의 코드 영역은 프로세스와 독립된 공간으로 공유되고 데이터 영역은 각 프로세스별로 독립적으로
생성된다.<br/>

## 암시적, 묵시적 링킹 (Implicit Linking)
프로그램 컴파일 시점에 dll 파일 정보를 심어두고<br/>
프로그램이 시작될 때 라이브러리 로드(종료 시에 해제)<br/>

```c++
// 암시적 연결 dll 생성
// MyDll.h
#pragma once
// MYDLL_EXPORTS가 정의되어 있으면 MYDLL 키워드는 export로
#ifdef MYDLL_EXPORTS
#define MYDLL __declspec(dllexport)

// MYDLL_EXPORTS가 정의되어 있지 않으면 MYDLL 키워드는 import로
#else
#define MYDLL __declspec(dllimport)
#endif

extern "C" {
  // __declspec(dllexport) 내용이 하나도 없으면 .lib가 생성되지 않ㄴ느다.
  // extern 키워드는 클래스에 쓸 수 없다.
}

// MyDll.cpp
#define MYDLL_EXPORTS
#include"MyDll.h"



// main.cpp, 본 프로젝트에서 사용
#pragma comment(lib, "MyDll.lib")
#include"MyDll.h"

int main() {
  
}
```

## 명시적 링킹 (Explicit Linking)
런타임 중에 원하는 시점에 로드하고 해제할 수 있다.<br/>
GetProcAddress()로 함수 주소를 가져와 사용해야 한다.<br/>
라이브러리 빌드 후 .dll 파일만 실행 파일 경로에 있으면 된다.<br/>

```c++
// 명시적 연결 dll 생성
// MyDll.h
#pragma once

class MyDll {
public:
  virtual ~MyDll();
  void Init();
};

extern "C" {
  __declspec(dllexport) MyDll* Create();
  __declspec(dllexport) void Destroy(MyDll* obj);

  __declspec(dllexport) void Init(MyDll* obj);
}

// MyDll.cpp
#include"MyDll.h"
#include<iostream>

void MyDll::Init() { std::cout << "Init" << std::endl; }

MyDll* Create() { return new MyDll(); }
void Destory(MyDll* obj) { obj->~MyDll(); }
void Init(MyDll* obj) { obj->Init(); }

// Main.cpp, 본 프로젝트에서 사용
#include<windows.h>

// 함수 포인터
void*(*Create)();
void(*Destroy)(void*);
void(*Init)(void*);

int main() {
  // Dll 로드
  HMODULE hDll = LoadLibrary(L"MyDll.dll");
  if (hDll == NULL) return 0;

  // 함수 주소 가져오기
  Create create = (Create)GetProcAddress(hDll, "Create");
  Destroy destroy = (Destroy)GetProcAddress(hDll, "Destroy");
  Init init = (Init)GetProcAddress(hDll, "Init");
  if (!create || !destroy || !init) {
    FreeLibrary(hDll); return 0;
  }

  // 사용
  void* myDllObj = create();
  init(myDllObj);

  FreeLibrary(hDll);
}
```

### 알아야할 내용
#### extern "C", Name Mangling
C++은 함수 오버로딩(동일한 이름의 함수를 매개변수만 다르게 하여 여러 개 정의)을 지원하기 위해
컴파일 시 함수의 이름을 내부적으로 변경하는 Name Mangling을 수행한다.<br/>

이로 인해 dll에서 함수를 내보낼 때(export), 사용하는 곳에서 함수 이름을 찾지 못하는 일이 생길 수 있다.
이를 방지하기 위해 extern "C"를 사용하여 C언어 스타일로 이름을 고정한다.<br/>

전역 변수, 전역 함수에 대해서 사용. 그 외 제약 사항에 대해서 알아본다.

클래스, 멤버 함수
클래스 내부의 메서드나 생성자, 소멸자는 c 언어에 없는 개념으로 extern c를 사용할 수 없다

함수 오버로딩
c에서는 함수 오버로딩이 없다. 

네임 스페이스
c에서는 네임 스페이스가 없다.

### dllexport, dllimport
dllexport
라이브러리 안의 특정 함수, 변수, 클래스를 외부에서 접근할 수 있도록 외부에 공개
컴파일 시 컴파일러가 해당 기호들을 dll의 내보내기 테이블에 등록

dllimport 함수 가져오기
호출하려는 함수나 변수가 현재 프로젝트 내부가 아닌, 외부 dll 파일에 있다는 것을 컴파일러에게 알려준다.
컴파일러가 불필요한 내부 탐색을 줄이고, dll 함수를 효율적으로 호출할 수 있도록 최적화

### 정리
#### 전역 변수
프로그램 전체(모든 TU)에서 접근 가능, extern 키워드를 사용하면 외부에서 사용 가능.<br/>

#### static 변수
해당 TU에서만 접근 가능.

```c++
int g_Num = 10;

void func() {
  static int static_Num = 5;
  cout << static_Num++ << endl;
}

int main() {
  func();
  func();

  // static_Num; <- 접근 불가능, 에러
  g_Num; // OK
}
```

#### extern 키워드
extern 키워드는 컴파일러에게 "이 변수의 실제 알맹이는 다른 파일에 있으니까 이름표만 보고 일단 번역해 줘.
나중에 링크 단계에서 진짜 변수랑 연결해 줄 거야."라고 알려주는 것.<br/>

```c++
// a.cpp
int a_Num = 10;

// main.cpp
// a include 없음
extern int a_Num;

int main() {
  cout << a_Num << endl; // 출력 OK
}
```
