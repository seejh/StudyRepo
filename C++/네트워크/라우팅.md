# 라우팅
경로 결정

* 라우팅 방식
  * 정적 라우팅, 동적 라우팅
    * 정적 라우팅
      * 관리자가 직접 경로 입력
    * 동적 라우팅
      * 라우터 간의 정보 교환으로 라우터가 경로 결정

* 아래와 같이 네트워크가 구성되어 있다고 하자
  * <img width="1217" height="518" alt="image" src="https://github.com/user-attachments/assets/8eef3b03-a934-4495-933f-43ff1b0315ee" />
    * 라우터에 직접 연결된 경로는 라우팅을 수행하지 않아도 라우팅 테이블에 기본적으로 등록되며 코드가 C로 올라온다.
    * 그러나 이 상태에서 송신지(10.0)에서 수신지(20.0)로 데이터를 보낼 수는 없다.
    * 라우터는 데이터가 들어왔을 때 패킷의 3계층 헤더에 들어간 목적지 ip 주소를 자신의 라우팅 테이블에서 찾는다.
    * 없다면 패킷을 폐기하게 되며 통신을 할 수 있게 만들기 위해 필요한 것이 라우팅이다.
  * <img width="1200" height="89" alt="image" src="https://github.com/user-attachments/assets/a7827442-6b10-4f52-9798-68be43b5086a" />
    * 192.168.20.0, 192.168.10.0 대역을 관리자가 직접 입력하면 정적 라우팅.
    * 라우팅 프로토콜을 통해 라우터간에 정보를 교환하고 교환된 정보를 바탕으로 라우터가 최적 경로를 계산, 결정하면 동적 라우팅.

* OSPF (Open Shortest Path First)
  * 동적 라우팅, 가장 많이 사용, 국제 표준 라우팅 프로토콜(어느 장비에서도 사용 가능)
  * 링크 상태 정보를 교환하는 링크 상태 라우팅 프로토콜
  * LSA (링크 상태 정보, 원래는 Link State Advertisement)
  * ip 주소, 서브넷 마스크, 연결된 네트워크 종류 등 링크의 모든 상태 정보
  * 링크: 라우터에 연결된 인터페이스로 R2의 경우 fa0/1, se0/1이고 R1의 경우 fa0/0, se0/0이 LSA로 날라간다.
  * 라우터에 연결된 인터페이스 정보 교환
  * OSPF는 30분마다 주기적인 업데이트, 토폴로지 변경이 발생하면 즉시 업데이트
  * OSPF는 3가지 테이블을 가진다.
  * Neighbor 테이블
  * Hello 패킷을 교환해 인식된 라우터의 정보가 등록되는 테이블
  * LSDB 테이블
  * OSPF에서 교환된 모든 링크 상태 정보가 등록되는 테이블
  * Routing 테이블
  * 모든 링크 상태를 가지고 있는 LSDB 테이블에서 SPF 알고리즘을 통해 결정된 최적의 경로가 등록되는 테이블

* OSPF 동작
  * 1.OSPF 네이버 관계
  * OSPF가 동작하는 라우터를 인식하기 위해 Hello 패킷을 교환하게 된다.
  * Hello 패킷을 교환 후 네이버가 되고 이를 네이버 관계라고 한다.
  * 관계를 맺은 후에도 이 관계를 유지하기 위해서 10초마다 hello 패킷을 보낸다.
  * hello 패킷 구성
  * 라우터 ID
  * 헬로 간격과 데드 간격
  * 영역 ID
  * 라우터 우선순위
  * DR ID 주소와
