# 이더넷 (Ethernet)
LAN(물리, 데이터 링크)에서 사용되는 기술. 특히 유선랜은 대부분 이더넷.<br/>
다양한 통신 매체의 규격, 송수신되는 프레임 형태, 프레임을 주고 받는 방법 등이 정의되어 있다.<br/>
이더넷 표준에 따라 지원되는 "네트워크 장비, 통신 매체의 종류, 전송 속도" 등이 달라진다.<br/>

## 통신 매체
물리 계층. 데이터를 주고 받는 통로.<br/>
컴퓨터의 디지털 신호를 변환해서 전달하는 케이블이나 전파<br/>

케이블의 규격 표기<br/>
```
전송 속도Base-추가 특성
ex) 1000BASE-SX, 5GBASE-T

전송 속도
기본 단위는 Mbps(G일 경우 Gbps)
해당 속도는 실제 처리율(throughput)이라기 보다는 대역폭으로 생각하는 것이 좋다.

추가 특성
통신 매체의 특성을 명시하는데 다양한 특성이 명시될 수 있다.
전송 가능 최대 거리, 물리 계층 인코딩 방식, 레인 수, 통신 매체 종류 등.
이 중에서 알아둬야 할 것은 통신 매체 종류

C : 동축 케이블<br/>
T : 트위스티드 페어 케이블<br/>
S : 단파장 광섬유 케이블<br/>
L : 장파장 광섬유 케이블<br/>

ex)
100GBASE-LR4 <- 장파장 광섬유 케이블, 4레인
1000BASE-CX <- 동축 케이블, x는 인코딩 방식
```

* 트위스티드 페어 케이블(twisted pair cable)<br/>
구리선으로 전기 신호를 주고 받는 통신 매체<br/>
구리선은 노이즈에 민감하기에 차폐(shielding)로 구리 선 주변을 감싸 노이즈를 감쇠시키는 방식을 사용한다.<br/>

* 광섬유 케이블<br/>
광 신호(빛)를 주고 받는 통신 매체로 전기 신호를 사용하는 케이블에 비해 속도가 빠르고 더 먼 거리까지 전송한다.<br/>
노이즈로부터 간섭 영향도 적어서 대륙 간 네트워크 연결에도 사용한다.<br/>


## 이더넷 프레임 형식 (데이터 링크 계층 관련)

<img width="972" height="154" alt="image" src="https://github.com/user-attachments/assets/bfc8286a-0f2e-47f5-bcda-2e01688af134" /><br/>
"헤더+페이로드+트레일로"로 구성되어 있으며 송신시에 상위 계층 정보인 페이로드에 헤더와 트레일러를 더해서 보내고(캡슐화)
수신시에 헤더와 트레일러를 제거(역캡슐화) 후 상위 계층으로 보낸다.<br/>

* 프리앰블<br/>
8바이트(64비트) 크기의 필드로 제일 앞단에서 이것이 이더넷 프레임임을, 이더넷 프레임의 시작임을 알린다.
앞에서부터 7개의 바이트에 "10101010", 마지막 바이트에 "10101011"을 표기함으로써 알려준다.
송수신지 간의 동기화를 위해 사용되는 정보.

* 송수신지 mac 주소<br>
mac 주소=네트워크 인터페이스마다 부여되는 6바이트의 주소(16진수 12자리)<br/>
일반적으로 NIC(Network Interface Controller) 장치가 네트워크 인터페이스를 담당하며
mac 주소를 가지고 있으며 "일반적"으로 고유하고 변경되지 않는다.<br/>

* 타입/길이<br/>
타입 또는 길이<br/>
크기가 1500 이하일 경우(16진수로 05DC), 이 필드는 "프레임의 크기"를 의미<br/>
크기가 1536 이상일 경우(16진수로 0600), 이 필드는 "타입"을 의미<br/>

* 페이로드<br/>
최소 크기는 46byte이며 이보다 작은 경우는 패딩(padding)이 채워지고 주로 0이 채워진다.<br/>
최대 크기는 1500byte이며 따로 설정을 한다면 더 크게 할 수 있고 점보 프레임이라고 한다.<br/>

* FCS (Frame Check Sequence)<br/>
수신한 이더넷 프레임에 오류가 있는지 확인하기 위한 필드로 CRC라는 값을 비교함으로써 오류를 검출한다.<br/>



# NIC (Network Interface Controller)
<img width="410" height="202" alt="image" src="https://github.com/user-attachments/assets/f856a567-54ba-440d-b9fb-a4939c82b3c6" /><br/>
호스트와 유.무선 통신 매체를 연결하는 장비<br/>

장비 수준에 따라 성능(처리 속도)가 다르다.<br/>

FCS 필드를 토대로 오류를 검출하면 잘못된 프레임을 폐기한다.<br/>


# 통신 장비
물리 계층, 데이터 링크 계층 장비<br/>

* 리피터<br/>
물리 계층 장비. 전기 신호 감소 또는 왜곡 되는 것을 방지하기 위해 신호를 증폭시켜 주는 장비<br/>

* 허브<br/>
<img width="553" height="293" alt="image" src="https://github.com/user-attachments/assets/93e2df51-4890-487d-b8bb-343b9a5b005c" /><br/>
물리 계층 장비로 요새는 잘 사용하지 않는다. <br/>
여러 호스트들을 연결시키는 물리 계층 장비이기에 주소 개념이 없기에 전달 받은 신호를 다른 모든 포트로 그대로 다시 보내는 방식으로 통신을 한다.
(불필요한 트래픽 많이 발생)<br/><br/>
반이중 방식(half duplex, 양방향 전송이 가능하나 동시에는 불가능한 방식 ex.무전기)으로 동시에 신호를 보내려고 하면 충돌이 발생한다.
연결된 호스트들의 수가 많을수록 충돌 가능성도 높아지고 이를 방지하기 위해 허브에서는 CSMA/CD라는 프로토콜을 사용한다.<br/>

* 충돌(collision)<br/>
허브는 주소 개념이 없어서 받은 패킷을 본인 포트를 제외한 모든 포트로 보낸다. 만약 a가 b에게 데이터를 보내는 와중에
c가 d에게 데이터를 보내면 a와 d의 신호가 부딪혀 손상되게 된다.<br/>

* CSMA/CD (Carrier Sense Multiple Access with Collision Detection)<br/>
충돌 방지 프로토콜<br/>
  * 캐리어 감지 (Carrier Sense)<br/>
  통신 매체의 사용 가능 여부 확인(현재 전송중인 것이 있는지) 후 전송<br/>
  * 다중 접근 (Multiple Access)<br/>
  통신 매체 체크 후 전송함에도 충돌이 발생할 수 있다.<br/>
  * 충돌 감지 (Collision Detection)<br/>
  충돌이 감지되면 전송 중단, 충돌 발생을 알리는 잼 신호(jam signal)를 전송, 임의의 시간 대기 후 재전송한다.<br/>

* 스위치<br/>
앞서 요새 허브는 잘 사용하지 않는다고 했는데 그 이유는 CSMA/CD 프로토콜로 어느정도 충돌에 대한 문제를 완화할 수 있지만
근본적인 해결(수신자에게만 송신)은 아니기 때문이다.<br/><br/>
허브와 달리 특정 MAC 주소를 가진 호스트에만 프레임을 전달 가능하며 전이중 모드 통신을 지원한다. CSMA/CD가 필요하지 않다.



MAC 주소 학습 기능
특정 포트와 해당 포트에 연결된 호스트의 mac 주소의 관계를 기억하여(매핑) 원하는 호스트에만 프레임을 전달한다.
<img width="555" height="180" alt="image" src="https://github.com/user-attachments/assets/47e8e147-c24f-4ffa-ab7b-e62c77b63b43" /><br/>

이 매핑 정보는 스위치 내부 메모리 공간에 맥 주소 테이블이라는 것을 만들어서 기억한다.(아래 그림)<br/>
<img width="534" height="213" alt="image" src="https://github.com/user-attachments/assets/aeb40059-fb48-4568-9026-287839b74213" /><br/>

스위치가 포트와 mac 주소를 매핑하고 관리하는 원리는 아래와 같다.
주소 학습(Learning)
a가 패킷을 보낼 때 패킷 안에는 보내는 사람의 주소도 있다. 스위치는 "1번 포트로 들어온 출발지 주소가 a네?"하고 1번 포트=a라고
매핑 테이블에 기록한다.

전달(forwarding)
이제 다른 쪽(b)에서 a에게 패킷을 보내면 스위치는 맥 주소 테이블을 확인해서 a가 1번 포트라는 것을 확인하고 1번 포트에만 보낸다.

다 보내기(flooding)
만약 아직 주소록에 없는 c의 패킷이 오면 데이터를 보낸 포트를 제외한 모든 포트에 데이터를 전부 보내서 c를 찾는다.

지우기(aging)
사용한 지 오래된 정보는 장치가 연결 해제가 되었다고 생각하고 제거한다.

브릿지
네트워크 영역을 나눠서 콜리전 도메인을 나누거나 네트워크를 확장하는데 사용하는 장비.
MAC 주소 학습 기능(스위치의 기능)을 가지고 있으나 허브와 마찬가지로 스위치에 밀려서 잘 안쓴다고 한다.
다만 브릿지라는 용어는 많이 사용된다.(= 네트워크 구획 나눔, 네트워크 확장)

vlan(virtual lan) 기능
가상 LAN을 만들 수 있는 기능.
물리적으로는 한 스위치에 다 꽂혀 있으나 소프트웨어적으로 구획을 나누어 불필요한 트래픽(플러딩)을 줄임으로써
성능 저하를 방지한다.

논리적으로 LAN을 분리. 가상 LAN을 만들어(논리적) 구획을 나누어 불필요한 트래픽을 줄임으로서 성능 저하 방지(플러딩)
