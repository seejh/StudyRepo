# 이더넷 (Ethernet)
LAN(물리, 데이터 링크)에서 사용되는 기술. 특히 유선랜은 대부분 이더넷.<br/>
다양한 통신 매체의 규격, 송수신되는 프레임 형태, 프레임을 주고 받는 방법 등이 정의되어 있다.<br/>
이더넷 표준에 따라 지원되는 "네트워크 장비, 통신 매체의 종류, 전송 속도" 등이 달라진다.<br/>

## 통신 매체
물리 계층. 데이터를 주고 받는 통로.<br/>
컴퓨터의 디지털 신호를 변환해서 전달하는 케이블이나 전파<br/>

케이블의 규격 표기<br/>
```
전송 속도Base-추가 특성
ex) 1000BASE-SX, 5GBASE-T

전송 속도
기본 단위는 Mbps(G일 경우 Gbps)
해당 속도는 실제 처리율(throughput)이라기 보다는 대역폭으로 생각하는 것이 좋다.

추가 특성
통신 매체의 특성을 명시하는데 다양한 특성이 명시될 수 있다.
전송 가능 최대 거리, 물리 계층 인코딩 방식, 레인 수, 통신 매체 종류 등.
이 중에서 알아둬야 할 것은 통신 매체 종류

C : 동축 케이블<br/>
T : 트위스티드 페어 케이블<br/>
S : 단파장 광섬유 케이블<br/>
L : 장파장 광섬유 케이블<br/>

ex)
100GBASE-LR4 <- 장파장 광섬유 케이블, 4레인
1000BASE-CX <- 동축 케이블, x는 인코딩 방식
```

* 트위스티드 페어 케이블(twisted pair cable)<br/>
구리선으로 전기 신호를 주고 받는 통신 매체<br/>
구리선은 노이즈에 민감하기에 차폐(shielding)로 구리 선 주변을 감싸 노이즈를 감쇠시키는 방식을 사용한다.<br/>

* 광섬유 케이블<br/>
광 신호(빛)를 주고 받는 통신 매체로 전기 신호를 사용하는 케이블에 비해 속도가 빠르고 더 먼 거리까지 전송한다.<br/>
노이즈로부터 간섭 영향도 적어서 대륙 간 네트워크 연결에도 사용한다.<br/>


## 이더넷 프레임 형식 (데이터 링크 계층 관련)

<img width="972" height="154" alt="image" src="https://github.com/user-attachments/assets/bfc8286a-0f2e-47f5-bcda-2e01688af134" /><br/>
"헤더+페이로드+트레일로"로 구성되어 있으며 송신시에 상위 계층 정보인 페이로드에 헤더와 트레일러를 더해서 보내고(캡슐화)
수신시에 헤더와 트레일러를 제거(역캡슐화) 후 상위 계층으로 보낸다.<br/>

* 프리앰블<br/>
8바이트(64비트) 크기의 필드로 제일 앞단에서 이것이 이더넷 프레임임을, 이더넷 프레임의 시작임을 알린다.
앞에서부터 7개의 바이트에 "10101010", 마지막 바이트에 "10101011"을 표기함으로써 알려준다.
송수신지 간의 동기화를 위해 사용되는 정보.

* 송수신지 mac 주소<br>
mac 주소=네트워크 인터페이스마다 부여되는 6바이트의 주소(16진수 12자리)<br/>
일반적으로 NIC(Network Interface Controller) 장치가 네트워크 인터페이스를 담당하며
mac 주소를 가지고 있으며 "일반적"으로 고유하고 변경되지 않는다.<br/>

* 타입/길이<br/>
타입 또는 길이<br/>
크기가 1500 이하일 경우(16진수로 05DC), 이 필드는 "프레임의 크기"를 의미<br/>
크기가 1536 이상일 경우(16진수로 0600), 이 필드는 "타입"을 의미<br/>

* 페이로드<br/>
최소 크기는 46byte이며 이보다 작은 경우는 패딩(padding)이 채워지고 주로 0이 채워진다.<br/>
최대 크기는 1500byte이며 따로 설정을 한다면 더 크게 할 수 있고 점보 프레임이라고 한다.<br/>

* FCS (Frame Check Sequence)<br/>
수신한 이더넷 프레임에 오류가 있는지 확인하기 위한 필드로 CRC라는 값을 비교함으로써 오류를 검출한다.<br/>



# NIC (Network Interface Controller)

호스트와 유.무선 통신 매체를 연결하는 장비<br/>

# 통신 장비

* 리피터
  * 물리 계층(L1) 장비로 전기 신호 감소 또는 왜곡 되는 것을 방지하기 위해 신호를 증폭시키기 위해 사용.

* 허브
  * 물리 계층(L1) 장비로 요새는 잘 사용하지 않는다
  * 여러 호스트들을 연결시키는 장비로 물리 계층이기에 주소 개념이 없어, 전달 받은 신호는 그 신호를 받은 포트를 제외한 다른 모든 포트로 다시 보내는 방식으로 통신을 한다. (불필요한 트래픽 많이 발생)
  * 반이중 방식 (half duplex)
    * 양방향 전송이 가능하나 송신과 수신을 동시에 못함(ex.무전기)
    * 동시에 신호를 보내려고 하면 충돌이 발생한다.
  * 연결된 호스트들의 수가 많을수록 충돌 가능성도 높아진다.
  * 이를 방지하기 위해 허브에서는 "CSMA/CD"라는 프로토콜을 사용한다.

* CSMA/CD (Carrier Sense Multiple Access with Collision Detection)
  * 충돌 방지 프로토콜
  * 캐리어 감지 (Carrier Sense)
    * 통신 매체의 사용 가능 여부 확인(현재 전송중인 것이 있는지) 후 전송
  * 다중 접근 (Multiple Access)
    * 통신 매체 체크 후 전송함에도 충돌이 발생할 수 있다.
  * 충돌 감지 (Collision Detection)
    * 충돌이 감지되면 전송 중단 ->
    * 충돌 발생을 알리는 잼 신호(jam signal)을 모두에게 전송 ->
    * 각자 임의의 시간 대기 후 재전송

* 스위치
  * 앞에서 요새 허브는 잘 사용하지 않는다고 했는데 그 이유는 더 나은 선택지가 있기 때문이다.(스위치)
  * 전이중, 데이터 링크 계층(L2, 주소 개념인 MAC 주소 사용)
  * MAC 주소 학습 기능, VLAN
    * MAC 주소 학습 기능
    * 스위치의 각 포트에 연결된 호스트의 MAC 주소를 기억하여 원하는 호스트에게만 프레임을 전달
    * 맥 주소 테이블 (MAC Address Table)
      * 스위치 내부에 메모리가 있고 여기에 맥 주소 테이블이 있으며
      * "특정 포트 : MAC 주소" 형식으로 매핑 정보가 저장된다.
    * 스위치가 포트와 mac 주소를 매핑, 관리하는 원리는 아래와 같다. (시나리오)
      * 주소 학습 (Learning)
        * 누가 패킷을 보낼 때 해당 패킷 안에는 보내는 사람의 주소가 있다. 스위치는 "1번 포트로 들어온 출발지 주소가 a네? 1번=a"라고 매핑 테이블에 기록한다. 
      * 전달 (Forwarding)
        * 이 상태에서 b가 a에게 패킷을 보내면 스위치는 맥 주소 테이블을 확인해서 a가 1번 포트라는 것을 확인하고 1번 포트에만 보낸다.
      * 다 보내기 (Flooding)
        * 만약 아직 주소록에 없는 주소지c에 대한 패킷을 보내면 보낸 포트를 제외한 모든 포트에 데이터를 전부 보내서 c를 찾는다.
      * 지우기 (Aging)
        * 사용한 지 오래된 정보는 장치가 연결 해제가 되었다고 생각하고 제거한다.
      * VLAN (Virtual Lan) 기능
        * 가상으로, 논리적으로 LAN을 만들 수 있는 기능
        * 물리적으로는 한 스위치에 다 꽂혀 있어서 같은 LAN이지만 소프트웨어적으로 구획을 나누어 불필요한 트래픽(플러딩)을 줄임으로써 성능 저하를 방지한다.
        * 정적 VLAN, 동적 VLAN
          * 정적 VLAN (포트 기반)
            * 스위치의 실제 특정 포트들에 vlan들을 할당
            * "스위치 특정 포트 ~는 ~~ vlan이다"
          * 동적 VLAN (MAC 주소 기반)
            * "MAC 주소 ~는 VLAN ~~이다"

* 브릿지
  * 네트워크 영역을 나눠서 콜리전 도메인을 나누거나 네트워크를 확장하는데 사용하는 장비
  * MAC 주소 학습 기능(스위치의 기능)을 갖고 있기에 L2 장비
  * 허브와 마찬가지로 스위치에 밀려 잘 사용하지 않는다.
  * 다만 브릿지라는 용어는 많이 사용된다.(=네트워크 구획 나눔, 네트워크 확장)

# 네트워크 계층
물리 계층, 데이터 링크 계층이 LAN 내의 통신이라면 여기서부터는 타 LAN과의 통신을 하는 단계이다.<br/>
IP 주소 사용, 라우팅<br/>

* IP (Internet Protocol)
  * 주소를 지정하여 송수신 대상으로 지정할 수 있게 하는 것으로 2가지 핵심 기술이 있다.
  * 주소 지정, 단편화
    * 주소 지정
      * IP 주소란 걸 사용해서 주소를 지정한다.(ex. 192.168.1.1)
    * 단편화 (fragmentation)
      * 전송하려는 패킷을 쪼개는 것으로 한 번에 보낼 수 있는 최대 크기(MTU) 이하로 나눈다.
      * MTU (Maximum Transmission Unit)
        * 한 번에 전송 가능한 IP 패킷의 최대 크기로 일반적으로 MTU 크기는 1500
        * 쪼개진 패킷은 수신지에서 재조합된다.
        * <img width="948" height="288" alt="image" src="https://github.com/user-attachments/assets/3939304f-1fcd-4dac-9986-297915d4cd5d" />
        * <img width="593" height="346" alt="image" src="https://github.com/user-attachments/assets/6f901152-c47a-421b-a6bf-7dd7934fcc5e" />

* 식별자
  * 쪼개져서 도착한 패킷들이 어떤 메시지에서 쪼개졌는지 알기 위해 사용.
  * 전송할 때 데이터가 커서 단편화되는 파편들은 모두 같은 번호를 부여 받는다.
  * <img width="732" height="211" alt="image" src="https://github.com/user-attachments/assets/79ab77d5-3904-49ff-8ecd-ce20602a5cd0" />
* 플래그(flag)
  * 3비트 크기로 첫 번재 비트는 항상 0으로 현재는 사용하지 않는다.
  * 두 번째는 DF 비트(Don't Fragment)로 IP 단편화를 수행하지 말라는 신호
    * 1일 경우 "단편화 수행하지 마라", 0일 경우 "IP 단편화 가능하다"
  * 세 번째는 MF 비트(More Fragment)로 단편화된 패킷이 더 있는지를 나타낸다.
    * 1일 경우 "쪼개진 패킷이 아직 더 있다", 0일 경우 "이 패킷이 마지막이다"
* 단편화 오프셋 (fragment offset)
  * <img width="790" height="239" alt="image" src="https://github.com/user-attachments/assets/f99a8568-24f5-487c-b6c1-950b04e83dd2" />
  * 단편화된 조각들이 순서대로 도착하지 않을 수 있다.
  * 이 순서를 오프셋으로 표시되어 있다.
* TTL (Time To Live)
  * 패킷의 수명, 무의미한 패킷이 네트워크 상에 지속적으로 남아 있는 것을 방지하기 위함
  * 패킷이 라우터를 거칠 때마다 TTL이 1씩 감소하고 0 밑으로 떨어지면 폐기.
* 프로토콜
  * 상위 계층의 프로토콜이 무엇인지를 나타내는 필드
  * tcp=6, udp=17

<hr/>

* ARP (Address Resolution Protocol, 주소 결정 프로토콜)
  * 동일 네트워크(LAN) 내에서 IP 주소를 통해 MAC 주소를 알아내는 프로토콜
  * ARP 요청, ARP 응답, ARP 테이블 갱신
    * ARP 요청 (ARP Request)
      * "IP 주소 ~를 가지는 a의 MAC 주소가 어떻게 되는가" <- 이거를 브로드캐스트로 묻는다.
    * ARP 응답 (ARP Reply)
      * 다른 호스트들은 자기가 아니기에(다른 IP 주소) 폐기
      * 호스트 a는 자신의 MAC 주소를 유니캐스트로 응답한다.
    * ARP 테이블 갱신
      * 일정 시간이 지나면 삭제

* 단편화를 피하는 방법
  * IP 단편화 단점
    * 불필요한 트래픽 증가와 대역폭 낭비
    * 쪼개진 IP 패킷들을 하나로 합치는 과정에서 발생하는 부하도 성능 저하 요소
  * 고로 IP 단편화는 되도록 발생하지 않는 것이 좋다.
  * IP 패킷을 주고 받는 모든 노드의 MTU 크기 최소치에 맞춰 전송해야 한다.
  * <img width="820" height="260" alt="image" src="https://github.com/user-attachments/assets/390e0add-9df3-441b-bdab-75559cd0aaa1" />
  * IP 단편화 없이 주고 받을 수 있는 최대 크기 = 경로 MTU (Path MTU)
  * 즉 단편화를 피하는 방법은 경로 MTU 만큼의 데이터를 전송하는 것
  * 경로 MTU 발견 (Path MTU discovery)
    * 경로 MTU를 구하고 해당 크기만큼만 송수신하여 IP 단편화를 회피하는 기술
  * 이렇게 단편화는 별로 좋지가 않기에 실제로 많이 일어나지 않는다.
  * 대부분 DF (Don't Fragment) 비트가 세팅되어 있다.

* IP 주소
  * IP 주소는 네트워크 주소와 호스트 주소로 구성된다.
  * 네트워크 주소
    * 호스트가 속한 네트워크 식별
  * 호스트 주소
    * 네트워크에 소속된 특정 호스트 식별

호스트 주소 공간을 크게 할당할 경우 => 호스트가 할당되지 않은 다수의 ip 공간 낭비
네트워크 주소 공간을 크게 할당하면 => 호스트가 사용할 ip 공간 부족

* 클래스풀(classful) 주소 체계
  * 위와 같이 ip 주소가 낭비되기 쉽기 때문에 이를 위해 네트워크 크기 별로 분류해 놓은 것
  * 클래스
    * a, b, c, d, e 클래스가 있으나 d, e는 멀티캐스트와 특수 목적을 위해 예약된 클래스
    * 실질적으로는 a, b, c 3개만 있다.
    * A 클래스
      * 가장 많은 수의 호스트를 할당할 수 있는 클래스

호스트 주소의 비트가 모두 0인 ip는 해당 네트워크 자체를 의미하는 네트워크 주소로 사용되고<br/>
호스트 주소의 비트가 모두 1인 ip는 해당 네트워크의 브로드캐스트 주소로 사용된다.<br/>

* 클래스리스 주소 체계 (classless addressing)
  * 클래스풀 주소 체계의 한계:호스트 개수가 C보다는 많은데 B는 애매한데(3만)
  * 네트워크 자리수, 호스트 자리수를 조금 더 세밀하게 조절할 수 있다.
  * 오늘 날 사용하는 방식
  * 세밀하게 조절하기 위해 서브넷 마스크, 서브네팅이라는 걸 사용한다.
  * 서브넷 마스크
    * ip 주소에서 네트워크 영역과 호스트 영역을 구분해주는 값으로 네트워크 주소로 몇 비트를 쓰는지 나타낸다.
    * ip 주소와 서브넷 마스크 값을 비트 AND 연산을 하면 네트워크 주소가 나온다.
    * 표기는 "ip 192.168.0.1 서브넷 마스크 255.255.255.0" 또는 "192.168.0.1/24"식으로 한다.
  * 서브네팅
    * 하나의 큰 네트워크를 여러 작은 네트워크(서브 네트워크)로 나누는 것
  * 예제로 이해: 192.168.0.0/24 네트워크 두 개로 쪼개기(서브네팅)
    * ip 주소    : 1100'0000.1010'1000.0000'0000.0000'0000
    * 서브넷마스크: 1111'1111.1111'1111.1111'1111.0000'0000
    * 네트워크 비트 하나 더 사용: 1111'1111.1111'1111.1111'1111.1000'0000 <-마지막 옥텟 첫 번째 비트 1로 변경
    * 192.168.0.0 네트워크와 192.168.0.128 네트워크 2개 생성
      * 192.168.0.0 네트워크, 호스트 사용 범위 "192.168.0.1~192.168.0.126"
      * 192.168.0.128 네트워크, 호스트 사용 범위 "192.168.0.129~192.168.0.254"
      * 앞자리 뒷자리 하나씩 부족한 것 같은데요? => 첫자리=네트워크 주소, 뒷자리=브로드캐스트 주소
      * 192.168.0.128 네트워크에서 호스트 192.168.0.129는 어떻게 표현?
      * "192.168.0.129/25" 또는 "ip 192.168.0.129 서브넷 마스크 255.255.255.192"
  
* ip 주소 분류
  * 공인 ip, 사설 ip
    * 공인 ip (public ip address)
      * 세계에서 고유한 ip 주소
      * 주로 isp(internet service provider)를 통해 제공 받음
    * 사설 ip (private)
      * 개인, 사설 네트워크에서 사용하기 위한 ip 주소로 사설 네트워크에서만 유효하다
      * 혹시라도 내 사설 네트워크 주소가 남의 공인 ip 주소면 어떻게?
        * 사설 네트워크를 위한, 사설 네트워크에서만 써야 하는 ip 주소가 내정되어 있다.
        * 10.0.0.0/8 - (10.0.0.0 ~ 10.255.255.255)
        * 172.16.0.0/12 - (172.16.0.0 ~ 172.31.255.255)
        * 192.168.0.0/16 - (192.168.0.0 ~ 192.168.255.255)
    * 사설 ip에서 공인 ip와 통신 어떻게?
      * NAT (Network Address Translation)
        * ip 주소 변환 기술로 주로 사설 ip(네트워크 내부)를 공인 ip(네트워크 외부)로 변환한다.
        * 라우터와 공유기는 NAT 기술이 내장되어 있다.
        * 자세한 건 나중에 배운다.
  * 동적 ip, 정적 ip
    * 호스트에 ip를 부여하는 방식이 정적이냐(정적 할당) 동적이냐(동적 할당) 하는 것
    * 정적 할당: 호스트에 직접 ip 주소 부여, 수작업
      * 호스트(윈도우 등)의 네트워크 설정에서 아래 내용 입력
        * ip 주소: 사용하고자 하는 ip 주소 번호
        * 서브넷 마스크: 내가 사용하고자 하는 네트워크의 서브넷 마스크
        * 게이트 웨이 주소 : 내부 네트워크의 라우터 주소
        * DNS 주소 : DNS 서버 주소, 나중에 제대로
    * 동적 할당: 호스트에 ip 주소를 부여하는 것을 프로토콜을 사용하여 할당
      * DHCP (Dynamic Host Configuration Protocol)
        * 이렇게 할당된 ip 주소를 동적 ip 주소라고 한다.
